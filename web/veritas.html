Self-correcting document Q&A

Answers from your documents, cited and checked before you see them.

Veritas reads messy PDFs, Word files, slides, spreadsheets and scans, keeps tables intact, and answers with page-level citations. When the passages don't hold the answer it searches again; when an answer isn't supported, it says so instead of guessing.

How it works

  1. ParseDocling reads layout and tables locally. Every table chunk repeats its header and section label, so a row keeps its meaning. Scanned pages go to a vision model.
  2. SearchMeaning-based and keyword search run in parallel, are fused, then reranked by a local cross-encoder. The best 5 passages are kept.
  3. AnswerThe generator answers only from those passages and cites each claim by file and page. A partial answer names what is missing.
  4. Correct itselfNothing relevant: rewrite into 3 searches. Part missing: search for exactly that part. Up to 2 rounds.
  5. CheckA second model verifies every claim against the passages. Unsupported answers trigger another search; out of retries, Veritas says it couldn't find it.

03

Built like a production system

Cost

Hard monthly spend cap with a ledger, cheap models with thinking off, cached repeats for $0, and evaluation at ~$0.20 per full run (down from several dollars).

Speed & scale

Streamed answers, parallel searches, a local reranker, a fallback with a circuit breaker; stateless app copies, an upload worker and shared Redis.

Accuracy

Hybrid search, table-aware chunking, vision for scans, targeted retries, a second-model grounding check, and "not found" instead of guessing.

Security

Prompt-injection guard for document text, CSRF protection, strict CSP and anti-framing headers, rate limits, upload limits and an optional password.

Known limits

  • One upload parses at a time; a 300-page book takes ~25 min on a laptop CPU, searchable as it goes.
  • Single tenant: one shared library and an optional password, not per-user accounts.
  • Not load-tested; the weakest spot is a noisy scanned tax table (neighbouring-row reads).
